# LEGACY Workflow (compatibility summary)

## 1. When it applies

- Cases without `workflow: "BUILDING"`.  
- Seed / historical example: **`CASE/2008-09/165`** — Mohan Vishwanath Gai, Dadulgaon.  
- Old measurement lines are **not** converted into BUILDING rooms.

## 2. Character of the legacy wizard

The earlier product narrative (see root `README.md`) describes a longer step sequence roughly covering:

1. Case identification & project mapping  
2. Property / LA metadata  
3. Structural specifications & lifecycle model (historically including long useful-life defaults)  
4. Multi-line measurements & opening deductions across CSR work groups  
5. Abstract estimate & CSR rate linking  
6. 7% Y.P. depreciation  
7. Second valuation / salvage materials abstract  
8. Master recapitulation & salvage adjustment  
9. Panchanama / photographic evidence  
10. Multi-page PDF certificate  

Exact UI chrome for LEGACY may differ from the six-screen BUILDING workspace; treat the README legacy section as the descriptive source for report writers who need more detail.

## 3. How to present this in the final report

| Recommendation | Reason |
|---|---|
| One short subsection under “System analysis” | Shows migration / compatibility |
| Do **not** make LEGACY the main proposed design | BUILDING is the forward path |
| Optional one screenshot of legacy case open | Only if time; not required for the pack’s core figures |
| State clearly that new cases use BUILDING | Avoid examiner confusion |
